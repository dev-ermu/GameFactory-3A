# 故事与剧本设计

创作能催生可玩性决策的故事，而非仅仅作为关卡间的文字段落。需匹配游戏类型、基调、受众、要求时长及制作限制。

## 基于现有素材展开设计

- **完整剧本**：保留角色、因果逻辑、必要场景及结局；将场景转化为可玩的情节节点。如有改动需明确说明。
- **部分剧本或设定梗概**：保留已给出的事实；填补缺失的动机、过渡环节及收尾内容，且改动处需清晰标注。
- **仅有需求说明**：先拟定剧情梗概、主角、核心诉求、阻碍因素、利害关系及结局，再起草从开头到结尾的简要大纲，最后细化章节内容。
- **非叙事类需求**：设计回合/进度流程，无需强行加入对话、主角或游戏并不需要的戏剧性弧光。

需维护一份简明的设定档案：记录角色及其目标、人际关系、世界规则、已发生的事件以及未解决的线索。区分用户提供的信息与创作者新增的内容。仅针对会实质性阻碍预期体验的选择进行询问。

## 构建因果逻辑链

遵循“铺垫 → 冲突 → 发现/决策 → 后果 → 收尾”的顺序排列情节。确保每个情节节点都有承接前一个节点的合理理由。尽可能将旁白转化为动作、观察、物品或简洁的对话。除非具备可玩性价值且对应资产成本可控，否则不得随意添加新角色、地点或过场动画。

每个场景或情节节点需明确标注以下内容：

| 要素 | 对应问题 |
|---|---|
| 时间与地点 | 该情节发生在何时何地？玩家如何抵达此处？ |
| 参与角色与意图 | 有哪些角色在场？他们知晓什么？他们的诉求是什么？ |
| 玩家能动性 | 玩家能做什么或做出什么选择，而非只能旁观？ |
| 变化结果 | 会产生哪些新知识、物品、人际关系或世界状态变动？ |
| 呈现方式 | 通过玩法、对话、环境叙事还是简短过场动画呈现？ |
| 过渡机制 | 什么条件能解锁下一个情节节点？若选择失败会发生什么？ |

为关键对话撰写实际样例：台词要简短、语气鲜明、明确标注选项内容及对应后果。切勿用“发生一段对话”这类表述代替具体脚本。分支选项需切实改变既定结局；标注出仅具装饰性的选择。

## 将情节节点排布在时间线上

需分别标注预估的游戏游玩时长与虚构的日期/时间。章节划分应依据目标、地点、认知、挑战或情绪基调的重大变化来定，而非随意按等长区间切分。若游戏类型允许，可交替安排动作、探索与反思环节。

每个章节需包含钩子、可玩目标、实质性变化及出口。明确标注分支走向、汇聚点、存档点及重试机制。可提前预告后续章节的需求，无需事先写全所有可选对话内容。

## 生成前需校验故事内容追踪各章节ID所对应的必要脚本节点。验证物品归属、所处位置、角色知晓的信息以及场景切换时的世界状态变化。确保任何分支路径都不会要求角色获取其根本无法得到的物品或事实，同时防止重复奖励现象的发生。还要确认结局能够呼应初始目标，且资源/页面清单涵盖了所有设定中的角色、环境及互动元素。
