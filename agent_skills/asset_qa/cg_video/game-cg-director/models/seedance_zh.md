# Seedance模型简介

```json machine-checks
{"model":"seedance"}
```

## 规范要求

- 将`prompt`表述为英语自然语言指令。用户提供的对话、歌词及可见文本需原样保留。
- 时长、比例、分辨率、随机种子、音频启用状态及其他API控制参数无需写入文本描述中；Harness会将这些参数作为请求参数传递。
- 不得使用H3标题、类XML的对话标签、图片对齐声明或保留标记，这些并非Seedance的语法规范。
- 除非针对具体部署的模型版本和任务类型经过验证，否则不得在此处注明时长或引用计数限制。

## 提示词构成规则

请按照以下顺序撰写提示词，不影响所需生成视频片段的部分可省略：

```text
<主体与场景锚点> + <可观测的动作> + <环境与光线> +
<摄像机与剪辑方式> + <视觉风格> + <声音> + <必要约束条件>
```

- 为每个反复出现的主体定义两到三个稳定且可见的特征，随后使用唯一明确的名称指代该主体，剪辑后不得更改其设定。
- 将抽象的情绪或氛围转化为可视化的表现：姿势、目光、表情、呼吸、速度、力度及反应。
- 将动作描述为因果序列，包含动作起始到结果的物理过渡过程。相比同时发生的多个冲突事件，优先选择几个易于理解的动作。
- 使用标准镜头术语，如远景、特写、固定镜头、推拉镜头、摇镜、跟拍或切镜。每个镜头对应一种主要的摄像机运动方式。
- 仅说明影响验收标准的约束条件，例如身份稳定、构图完整、无字幕、无logo等。避免使用冗长的通用负面提示词列表或相互矛盾的形容词。

## 连续镜头描述

简单连续镜头用一段文字描述即可。若视频需要剪辑，则按播放顺序撰写简短段落：

```text
整体描述：<稳定的角色、场景、视觉处理方式及连贯性锚点>。
镜头1：<取景或摄像机设置> + <主体动作> + <空间变化> + <声音>。
镜头2：<切镜或摄像机设置> + <主体动作及结果> + <声音>。
约束条件：<本任务所需的特定约束>。
```

- 镜头按顺序编号，每个镜头聚焦于新的信息。
- 默认无需指定精确的时间戳范围。仅当用户要求同步时才会使用时间信息；否则可用“首先”“接着”“之后”“最后”等词语表达顺序与节奏。
- 音效、台词或音乐变化需标注在对应的镜头中。若有必要，需说明声源、出现时机、强度及可听变化。

## 参考素材绑定规则

按照输入顺序为参考素材编号，并为每个素材分配明确的用途。当涉及相关素材时，使用API风格的标记`@Image N`、`@Video N`和`@Audio N`；切勿用文件名或资源ID替代这些标记作为提示词内容。- 主体参照：`将@Image 1中的红色装甲飞行员设为玩家；需保留其头盔轮廓与胸前的徽章。`
- 属性迁移：`仅采用@Image 2的光照与调色板效果；不得照搬其主体、姿势或构图。`
- 动作/镜头参照：`在遵循上述玩家与竞技场设定的前提下，跟随@Video 1的镜头运动。`
- 音频参照：匹配@Audio 1的打击乐节奏；将撞击重音与最终击打动作同步。

对于多个主体，需在镜头段落前逐一定义，后续所有操作中均使用同一名称。引用时不得悄悄代入无关的身份、背景、姿势、镜头、风格或声音设定。

### 模式表述规则
- T2VA：直接说明主体、场景与初始构图，无需使用引用标记。
- I2VA：需表述为“将提供的第一帧用作精确的初始构图”，指明开始移动的元素，同时保留所有未提及的可见元素。
- FL2VA：需表述为“从提供的第一帧开始，到提供的最后一帧结束”，描述的是可实际实现的过渡过程，而非两个互不关联的端点描述。
- Ref2VA：先定义各引用角色，再说明每个角色生效的镜头或事件。
