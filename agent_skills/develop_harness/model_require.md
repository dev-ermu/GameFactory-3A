# model_require.md — `models/` 目录的规范

`<REPO_PATH>/models/` 下的文件是**对单个云端模型的精简封装**。它知晓该模型的服务商、原生API、版本标识与请求参数格式，完全不了解任务、jsonl 文件、游戏项目或输出目录相关信息。

> **为了让消费级设备也能运行，本仓库不考虑使用本地权重模型，使用云端大模型API**。如Tripo、Meshy、Seedream、Seedance、Seed Audio 等。

> 必需接口：每个模型都必须实现 `__init__()` 和 `request()`。
> 每个模型对应一个文件：`<REPO_PATH>/models/<家族名>/<模型名>_model.py`，类名为 `<名称>Model`。
> 模型专用的辅助函数应放在`<REPO_PATH>/models/<家族名>/<模型名>_utils/`目录下。

示例：
- 生成类模型：`<REPO_PATH>/models/gen_3d_object/tripo_model.py`、`<REPO_PATH>/models/gen_image/seedream_model.py`

参考实现：`<REPO_PATH>/models/gen_3d_object/tripo_model.py`；共享的 HTTP／重试／缓存逻辑见 `<REPO_PATH>/models/common/cloud_api.py`。

## R1 — 硬性规则

| 编号 | 规则 | 原因 |
|---|------|-----|
| R1.1 | **禁止从 `<REPO_PATH>/operators/` 或 `<REPO_PATH>/pipeline/` 导入任何内容。** | 依赖关系只能向下传递。 |
| R1.2 | **绝不构造输出路径。返回内存中的数据（PIL / numpy / tensor / trimesh / bytes）**。 | 输出文件的存放由操作符模块负责。 |
| R1.3 | **禁止使用`argparse`，也不得编写`if __name__ == "__main__"`相关的业务逻辑。** | 命令行接口功能由`run.py`实现。 |
| R1.4 | **不涉及任务语义。不得使用`task_id`、`game_id`，也不得为特定任务编写提示词模板**。| 提示词相关逻辑属于`<REPO_PATH>/operators/<任务名>/funcs/`目录。 |
| R1.5 | 重量级依赖若属于可选依赖，应放在 `__init__` 或 `_load()` 内部，以便该模块能仅在需要的时候被导入。 | `<REPO_PATH>/tests/harness/smoke.py` 必须能在没有任何云端凭证的情况下导入整个流程链。|
| R1.6 | 当缺少环境前提条件时，需快速终止任务(避免消耗token)，抛出错误信息，提醒用户。 | 见 `tripo_model.py`中对缺失API Key的检查逻辑。 |

### R1.2 — 唯一例外情况

仅当服务商返回的产物无法合理驻留内存时，才允许提供 `request_and_save(..., output_path)` 这类便捷方法（例如Tripo返回的GLB文件自带纹理图集）。相关要求如下：

- 输出路径由调用方传入，模型内部绝不能直接生成该路径；
- 需对父目录执行`mkdir(parents=True, exist_ok=True)`操作；
- 该方法需返回路径字符串；
- 模型中必须同时存在返回内存数据的`infer()`方法。

### R1.2.1 — 可选的中间过程观测功能

此功能为可选，默认禁用。模型可以设置`observe_intermediates=False` 和/或 `on_intermediate=None`，以返回用于调试或监控的内存中的中间阶段元数据。除非明确启用，否则模型不得计算、打印或保存中间结果；显示、持久化及审核功能由操作符/流水线模块负责。

## R2 — 构造函数

```python
def __init__(self, model_id: str = "模型ID/模型名", **model_specific):
```

| # | 规则 |
|---|------|
| R2.1 | `model_id`携带的是**模型ID，调用API时需要使用**，如`"doubao-seed-2-0-mini-260428"`。 |
| R2.2 | 在发起任何请求前，需将所有构造函数参数存储到 `self` 中。 |

## R3 — 推理规则

当前页面上的云服务厂商通常会提供OpenAI Chat Completions协议格式API，同时由于后续OpenAI推出新的协议Responses API（官方），另外Anthropic也提供一种Messages API格式。

OpenAI的两种格式都需要OpenAI这个Python包。Anthropic Message API则需要anthropic官方python包。

| # | 规则 |
|---|------|
| R3.1 | 如果模型服务支持，则使用OpenAI官方Python，使用OpenAI Response API格式。不支持则考虑Chat Completions格式，Anthropic Message API格式。若都不支持，则需要浏览服务商官方文档，寻找API接入方式，通常是服务器提供了自己的方法，例如Tripo API服务有自己的接入方式。|
| R3.2 | 接收输入**对象**，而非文件路径。支持 `Image.Image`、`np.ndarray`、字符串提示词，绝不允许传入 `"path/to/x.png"` 这类路径。 |
| R3.3 | 若服务商支持，则将`seed`参数传递给服务端；否则该参数被接收但忽略。 |
| R3.4 | **服务端生成结果的可复现性无法得到保证**。文档字符串中必须注明这一点。绝不能通过本地设置随机种子来伪造可复现性。|
| R3.5 | 返回类型需在文档字符串中明确说明且保持稳定，不得直接返回裸元组。 |
| R3.6 | **代码中不得使用 `@torch.no_grad()` 或 `torch.inference_mode()`，也不不得导入`torch`模块**。本地大模型不存在，梯度上下文也无从谈起。 |
| R3.7 | 除非显式开启`verbose`标志，否则不得打印进度信息。 |

## R4 — 会话与生命周期

云端后端在调用之间**不驻留任何资源**，因此不存在显存管理问题。

| # | 规则 |
|---|------|
| R4.1 | 默认使用keep-alive连接池。 |
| R4.2 | 使用previous_response_id参数维护会话，若是需要修改已生成的资源，则继续使用上次的会话。|

---

## R5 — 远程任务模型

| # | 规则 |
|---|------|
| R5.1 | 基于任务的API（提交任务 → 轮询状态 → 下载结果），优先考虑官方库提供的接口实现。 |
| R5.2 | `timeout` 和 `poll_interval` 是构造函数参数。`timeout` 的默认值应设得**较长**（生成任务可能耗时数十分钟）。 |
| R5.3 | 超时抛出的错误信息中**必须包含 `task_id`**，以便人工恢复仍在服务端运行的任务。 |

> R5.2 的理由是不对称的：超时**不退款**——任务会在服务端继续执行，损失的只有下载环节。因此设置较短的超时会在最需要结果的时刻浪费整笔额度，而设置较长的超时不会多消耗任何额度。

## R6 — 凭证与端点

| # | 规则 |
|---|------|
| R6.1 | **API Key或API Base URL在构造对象时读取**。 |
| R6.2 | 若API Key或API Base URL缺失，应快速报错，同时指明缺失的**配置项名**。 |
| R6.3 | **API基础URL是必填项，不可设置默认值，代码实现不允许随意猜测**。服务商可能随时更换API基础URL。 |
| R6.4 | 相信用户填写的API key，API Base URL。调用API时直接输入，不要进行再次URL拼接，或修改URL。 |

---

## R7 — 缓存与计费

每次真实API调用都会产生费用。

| # | 规则 |
|---|------|
| R7.1 | 资源生成之后，不管结果是否令人满意，都要将生成结果存储到磁盘。除非用户自行删除，否则代码不允许丢弃资源。 |
| R7.2 | 每次真实API调用都需记录`task_id`、耗时、消耗的额度（若有返回）以及输出大小。 |

---

## R8 — 重试与错误分类

网络故障属于常态，而非例外情况。

| # | 规则 |
|---|------|
| R8.1 | 支持带指数退避的 `max_retries` 参数。 |
| R8.2 | 区分**可重试**故障（5xx、429、连接重置、读取超时）与**终态故障**（400 参数错误、401/403 认证错误、402 余额不足、任务被拒绝）。**绝不要重试终态故障。** |
| R8.3 | 分类依据是**响应体**而非仅状态码：某些服务商在返回认证相关状态码时，提示的其实是"余额不足"，仅看状态码无法区分它与密钥错误，调用方必须能分辨二者。 |

---

## R9 — 输出格式

| # | 规则 |
|---|------|
| R9.1 | `output_format` 是构造函数参数，比如默认值为"glb"。 |
| R9.2 | 若服务商无法原生支持某种格式，必须抛出**可操作的终态错误**并指明替代格式——绝不能悄悄返回其他格式。 |

---

## R10 — 共享逻辑与配置源

| # | 规则 |
|---|------|
| R10.1 | 所有API Key、API Base URL、后端选择都从**同一个来源**读取：`<REPO_PATH>/config.py`（加载`<REPO_PATH>/.env`）。封装层不得自行定义环境变量名、读取自身的 `.env`，或硬编码配置项值。 |
| R10.2 | `config` 特意设计为**顶层的、仅使用标准库**的模块：`models/` 不能导入 `pipeline/`（R1.1），而这两层需共用同一套配置，因此它不属于任何一方。 |
| R10.3 | Pipeline 运行器会在加载任何内容前，于 `main()` 中调用 `pipeline.common.config.require_cloud_or_exit(...)`，以便第一时间报告配置错误。凭证缺失时该任务根本不会运行，运行器以**退出码 2** 结束。 |

---

## R11 — 模型可替换性

相同功能的AI大模型，比如3D建模AI大模型`TripoModel`与`MeshyModel`，必须符合相同接口规范（继承同一个基类），以便`<REPO_PATH>/operators/gen_3d_object/operator.py`无需改动即可切换后端。

为现有插槽添加第二个后端时需注意：

1. 必须与现有的函数签名及返回类型完全一致；
2. 需将其添加到`<REPO_PATH>/models/README.md`的候选模型表中。

## R13 — 文档字符串模板

```python
"""
<Name>Model — <一句话说明：它封装了什么以及输出结果是什么>。

参考来源：<服务商开发者文档 URL>

<环境前置要求：所需的环境变量名、可选的鉴权说明。>

使用示例：
    from models.<家族名>.<模型名>_model import <Name>Model
    model = <Name>Model(model_path="<version-id>")
    out = model.request(image, seed=42)
"""
```

每个公开方法都需注明参数（`Args`）、返回值（`Returns`），若是数组类型还需说明**形状及数值范围**。

## R14 — 检查清单

结构与接口：
- [ ] 一个文件对应一个模型，文件名为 `<模型名>_model.py`，类名为 `<Name>Model`
- [ ] `<REPO_PATH>/models/<家族名>/__init__.py` 中已导出该模型
- [ ] `model_id` 的是一个真实的服务商版本字符串，无默认值。
- [ ] 无需API密钥、无需网络访问即可实例化`Model()`
- [ ] 不从`<REPO_PATH>/operators/`或`<REPO_PATH>/pipeline/`导入任何内容
- [ ] 未在代码内部构造输出路径（或 `output_path` 确由调用方传入）
- [ ] 返回类型已文档化
- [ ] 已将其添加到`<REPO_PATH>/models/README.md`的表格中

云端调用：
- [ ] 缺少密钥时，报错信息说明配置项名称与当前`.env`路径（R6.2）
- [ ] 缺少API Base URL时同样报错；文档中的端点示例仅供参考，无法保证永远有效。（R6.3）
- [ ] 400 / 401 / 402 等终态错误不会触发重试（R8.2）
- [ ] 真实请求记录了 `task_id`、耗时、消耗额度与输出大小。

## 成本与许可说明

- 免费套餐的额度有限。建议先通过**测试**验证整体流程；仅在实际最终验证阶段才消耗真实积分。
- API密钥与API Base URL配置存储在`<REPO_PATH>/.env`，通过`<REPO_PATH>/config.py`读取（R10.2）。API Key绝不允许出现在代码仓库、日志、`meta.json`或其它任何文件名中。
- 各服务商的免费版与付费版套餐在商业使用权限上存在差异。发布任何生成内容前务必确认对应的套餐类型。
