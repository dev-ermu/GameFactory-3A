# api_model_require.md — 针对闭源云API的`model_require.md`补充文档

`model_require.md`是为**本地权重**模型编写的：你拥有模型权重、运行设备和处理流程。而围绕**闭源云API**（Tripo、Meshy、Rodin、ElevenLabs、Kling等）的封装会打破其中的一些预设——不存在权重路径，没有运行设备，也没有`torch`；推理是远程*任务*而非简单的函数调用，每次调用都要付费，且网络故障也时有发生。

本文档在`model_require.md`的基础上新增了**R9**规则。R1–R8中未被此处明确覆盖的内容仍然适用，尤其是R1.1（禁止从`<REPO_PATH>/operators/`或`<REPO_PATH>/pipeline/`导入内容）、R1.2（切勿构造输出路径）、R1.4（不使用任务语义）以及R6（可互换性）。

> 可将`<REPO_PATH>/models/gen_3d_object/tripo_model.py`作为参考实现，共享的HTTP/重试/缓存相关逻辑可参考`<REPO_PATH>/models/common/cloud_api.py`。

---

## R9 — 云API封装| # | 规则 | 制定理由 |
|---|------|-----------|
| **R9.1** | `model_path` 参数携带的是**模型版本标识符**（如 `"v3.1-20260211"`、`"meshy-6"`），而非权重文件存储路径。需保持该参数的名称与位置不变——调用方无需为此写额外的分支逻辑。 | 该规则覆盖了R2.1和R2.2的规定。 |
| **R9.2** | `device` 参数仅用于保证接口兼容性，实际会被忽略。`device="cpu"` 场景下不应触发报错。需在文档字符串中说明这一点。 | 该规则覆盖了R2.3的规定。 |
| **R9.3** | 代码中不得使用 `@torch.no_grad()` 或 `torch.inference_mode()` 装饰器，也不得导入 `torch` 模块。 | 该规则覆盖了R3.6和R5.5的规定。 |
| **R9.4** | `unload()` 方法存在，具备幂等性且会关闭HTTP会话。该方法永远不会使缓存的凭证失效。 | 该规则覆盖了R4.1至R4.3的规定。 |
| **R9.5** | 若服务提供商支持，则会将 `seed` 参数传递给服务端；否则该参数会被接收但被忽略。文档字符串中必须注明**服务端生成结果的可复现性无法得到保证**。绝不能通过本地设置随机种子来伪造可复现性。 | 该规则覆盖了R3.3和R3.4的规定。 |
| **R9.6** | 基于任务的API（提交任务→轮询状态→下载结果）被封装在同步方法 `infer()` 之后。`timeout` 和 `poll_interval` 作为构造函数参数；超时的默认时长设置得**较长**（因为生成任务可能耗时数十分钟）。超时发生时抛出的错误信息中必须包含 `task_id`，以便人工恢复运行中的任务。 | R3.1仍对调用方保持同步特性。若预算耗尽则不会退款——任务会在服务端继续执行，仅下载环节会失败——因此设置较短的超时时长会浪费额度，而设置较长的超时时长则不会消耗额外额度。 |
| **R9.7** **API密钥**和**API基础URL**均在**首次调用时读取**，而非构造对象时读取。若两者缺失，应快速报错，同时指明缺失的变量名以及 `<REPO_PATH>/.env` 文件路径。API基础URL是**必填项，不可设置默认值**：由于公共端点并非在所有网络环境下都可访问，若默认使用某个地址，会导致看似配置正常，直到首次产生费用调用时才报错。需使用 `cloud_api.require_api_key()` 和 `cloud_api.require_api_base()` 来实现这一逻辑。 | 模型对象的构造过程不应要求提供凭证——因为 `<REPO_PATH>/tests/harness` 模块会导入该模型对象。错误的或无法访问的端点属于配置错误，不应在请求阶段才神秘地报错。 |
| **R9.8** | 支持 `cache_dir` 参数。对于由 `(model_path、提示词/图像哈希值、所有推理参数、输出格式)` 唯一标识的请求，若其结果已缓存，则**无需任何网络传输即可直接返回结果**。每次真实调用都会记录 `task_id`、耗时、消耗的额度（若有返回）以及输出结果大小。 | 每次调用都会产生费用。重新运行流水线时不应重复计费。 || **R9.9** | 支持带有指数退避机制的`max_retries`参数，同时能对故障进行分类：可重试的故障（5xx错误、429错误、连接重置、读取超时）与不可重试的终端故障（400参数错误、401/403认证错误、402余额不足、任务被拒绝）。绝不要对终端故障进行重试。分类依据是响应体而非仅状态码：某些服务商在返回认证相关状态码时，会提示“余额不足”，仅从状态码无法区分这种情况与密钥错误，调用方必须能区分二者。 | 网络故障属于常态，而非例外情况。 |

### R9.10 — 输出格式
`output_format`是构造函数参数（默认值为`"glb"`）。如果服务商无法原生支持某种格式，就必须抛出一条**可操作的终端错误**，并指明替代格式——绝不能悄悄返回其他格式。

### R9.11 — 共享通用逻辑的位置
HTTP会话、重试/退避机制、错误分类、响应缓存以及轮询循环等内容不会为每个服务商单独实现。它们存放在`<REPO_PATH>/models/common/cloud_api.py`中，可在不同功能族（`gen_3d_object`、`gen_audio`、`gen_cg_video`等）间共享。各服务商特定的请求体则仍由对应的封装层处理。

### R9.12 — 统一的配置源
所有凭证、基础URL、后端切换选项以及缓存位置都从**同一个地方**读取：`<REPO_PATH>/config.py`，该文件会加载`<REPO_PATH>/.env`（模板为`.env.example`）。封装层不得自行定义环境变量名称、读取自身的`.env`文件，或采用硬编码的端点地址。
特意将`config`设计为**顶层的、仅使用标准库**的模块：因为`models/`层不能导入`pipeline/`层（R1.1），而这两层需要共用同一套配置，所以它不属于任何一方。`models/common/cloud_api.py`会在模块加载时导入它，因此即便封装层在Pipeline运行器之外使用，也能访问到该配置文件。
对于每个指向云端后端的插槽，Pipeline运行器会在加载任何内容前，于`main()`函数中调用`pipeline.common.config.require_cloud_or_exit(...)`，这样能在第一时间就报告配置错误，而非等到第一个任务执行时才发现。若任务的云端凭证缺失，该任务根本不会运行；运行器会退出并返回代码**2**。

## 合约偏差标注 — 共三处，均为必填项
云服务商封装层出于设计原因会与`model_require.md`中的规定存在偏差。必须标注清楚，以免读者猜测这种偏差是否属有意行为。

**① 文件文档字符串中的`CONTRACT DEVIATIONS`章节**，每条规则占一行：
```python
"""
TripoModel — 围绕Tripo3D云端3D生成API的封装层。

参考链接：https://developers.tripo3d.ai/

合约偏差（model_require.md针对的是本地权重模型；详见agent_skills/develop_harness/api_model_require.md）：
  C1  R2.1/R2.2 → R9.1  `model_path`参数传递的是模型版本ID，而非权重文件路径。
  C2  R2.3      → R9.2  `device`参数虽被接收用于保持接口一致性，但会被忽略。
  ...
"""
```

**② 在出现偏差的具体代码行旁添加内联注释`# [CONTRACT-DEVIATION Cx]`**：```python
def __init__(self, model_path: str = "v3.1-20260211", device: str = "cuda", ...):
    # [契约偏差 C1] model_path 是模型版本标识，而非权重文件存储路径。
    # [契约偏差 C2] device 参数仅为了接口一致性而接受，实际会被忽略。
    self.model_path = model_path
    self.device = device
}

**③ 该文件**——此类偏差必须对应到 R9.1–R9.12 中的某一条规则；如果没有对应的规则，需先在此添加新规则。

### 标准偏差标识
请使用这些标识，以确保所有云封装层的处理逻辑一致。

| 标识 | `model_require.md` 对应条目 | 偏差描述 | 管控规则 |
|----|--------------------|-----------|-------------|
| C1 | R2.1 / R2.2 | `model_path` 是模型版本标识 | R9.1 |
| C2 | R2.3 | `device` 参数会被忽略 | R9.2 |
| C3 | R3.6 / R5.5 | 未使用 `torch.no_grad()` | R9.3 |
| C4 | R4.1–R4.3 | `unload()` 用于关闭会话 | R9.4 |
| C5 | R3.3 / R3.4 | `seed` 参数仅为尽力而为设置，无法保证结果可复现 | R9.5 |
| C6 | R3.1（隐含规则） | 提交请求→轮询状态→下载结果的过程被封装在阻塞式的 `infer()` 调用中 | R9.6 |
| C7 | R1.2 | `infer_and_save(..., output_path)`（属于R1.2中规定的例外情况） | — |
| C8 | （新增） | 使用 `cache_dir` 参数，相关请求会计费 | R9.8 |
| C9 | （新增） | 设置 `max_retries` 参数，允许网络请求失败重试 | R9.9 |

## 检查清单——除R8要求外还需满足以下条件
- [ ] `model_path` 的默认值是一个真实的供应商版本字符串；别名也被允许。
- [ ] 无需API密钥且无需网络访问即可实例化 `Model()`。
- [ ] 传入 `device="cpu"` 参数时不会触发错误。
- [ ] 若缺少必要密钥，应报错并说明对应的环境变量名称以及 `.env` 文件的指引。
- [ ] 若缺少基础URL配置，应报错并说明对应的环境变量名称以及 `.env` 文件的指引；文档中给出的端点示例仅作参考，绝不会作为回退选项（R9.7）。
- [ ] `infer()` 调用会一直阻塞直到任务完成；超时错误中会包含 `task_id` 信息。
- [ ] 终端返回的错误码为 400 / 401 / 402 时，不会进行重试。
- [ ] 缓存命中时不会发起任何HTTP请求。
- [ ] 真实请求会记录 `task_id`、耗时、消耗的积分以及输出文件大小等信息。
- [ ] 多次调用 `unload()` 不会有任何操作执行。
- [ ] `infer_and_save` 的函数签名与同一操作符槽位下的其他后端实现完全一致（R6）。
- [ ] `<REPO_PATH>/tests/harness/stubs.py` 中存在一个不会进行任何网络I/O的存根实现，且运行 `python tests/harness/smoke.py --kind <kind>` 命令时无需设置密钥即可通过测试。

## 成本与许可说明
- 免费套餐的额度有限。建议先通过**存根实现**验证流程；仅在实际最终验证阶段才消耗真实积分。
- API密钥和基础URL配置存储在 `<REPO_PATH>/.env` 文件中（模板为 `.env.example`），通过 `<REPO_PATH>/config.py` 读取相关配置（R9.12）。密钥绝不允许出现在代码仓库、日志行、`meta.json` 文件或缓存文件名中。
- 各供应商的免费版和付费版套餐在商业使用权限上存在差异。发布任何生成内容前务必确认对应的套餐类型。
