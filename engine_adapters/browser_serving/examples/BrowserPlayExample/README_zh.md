# 浏览器游玩示例

这是上游组装步骤完成后的最终交付阶段参考说明：
1. 生成Mechanic插件和原生UI插件；
2. 将它们整合为一个原生引擎项目或运行时产物；
3. 导入选定的资源并构建游戏世界；
4. 编译并验证该原生项目。

该示例并不会构建游戏玩法、导入资源、编译引擎项目，也不会实现浏览器服务端后端。它演示的是剩余的交付流程：

```text
准备好的原生项目及已注册的引擎后端
  -> 浏览器服务网关
  -> 引擎运行时会话
  -> stream_url
  -> 归属特定任务的 /game 浏览器页面
```

参考清单中的 `selected_by_packet` 等值仅为占位符。生成的输出内容必须将其替换为对应准备包中规范的引擎及已注册后端的实际值。

## 运行方式

通过Pipeline或操作员配置选定的引擎后端，随后在Windows系统上运行 `launch.cmd`，或在macOS/Linux系统上运行 `launch.sh`。Unix系统的启动器默认使用已验证的Unity后端；若要选择其他已配置的后端，需设置 `A3GAME_BROWSER_ENGINE` 变量。

启动器会通过 `A3GAME_BROWSER_PLAY_DIR` 挂载该目录，并启动公共网关入口点。打开以下地址即可访问：

```text
http://127.0.0.1:7870/game/?engine=unity3d
```

该页面会先对浏览器服务进行健康检查：若有已提供的或已存储的会话，则恢复该会话；否则为选定的引擎创建新会话，并将返回的 `stream_url` 显示在全屏框架中。流式传输的引擎框架内已经包含了原生游戏玩法UI。

Unity路径已在FPS生成游戏示例中验证：浏览器服务返回了 `unity_webgl` 会话，页面在iframe中加载了WebGL播放器，键盘/鼠标输入也能正常传递到Unity画布。

运行静态合约测试的命令如下：

```text
node tests/browser_play.test.js
```
