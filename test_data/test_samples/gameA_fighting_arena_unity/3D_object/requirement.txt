# 3D Object Generation Requirements — gameA_fighting_arena_unity

## Overview
Generate game-ready 3D models for the fighting arena game. All character models
are generated from T-pose reference images using Tripo or Meshy.
Weapon, prop, and architectural models are generated from reference images
using Tripo or Meshy.

## Model Backend
- **Characters**: Tripo / Meshy (T-pose image → 3D model)
- **Weapons / Props**: Tripo / Meshy (ref image → 3D model)
- **Architecture**: Meshy image-to-3D (ref image → textured GLB)

## Quality Requirements

### Character Models (Warrior, Ninja)
- Triangle count: ≤100,000 tris
- PBR textures: 2048×2048
- T-pose orientation: arms along X-axis, feet on ground plane
- UV-mapped, game-ready, rigged-ready topology
- Realistic style matching Mortal Kombat visual reference

### Weapon / Prop Models
- Triangle count: ≤10,000–15,000 tris
- PBR textures: 2048×2048
- UV-mapped, game-ready

### Architectural Models
- Triangle count: ≤70,000 tris
- Embedded PBR textures with readable wood, stone, metal, and roof surfaces
- Preserve open interiors and continuous walkable floors
- Use meters for target scale; gameplay collision is authored separately in-engine

## Output Format
- GLB (binary glTF) with embedded PBR textures
- Output path: test_data/outputs/gameA_fighting_arena_unity/<run_id>/assets/3d_object/<task_id>/model.glb

## Notes
- Character models must be in T-pose for subsequent rigging and motion retargeting
- All models must use consistent scale (meters, 1 unit = 1 meter)
- Warrior model should emphasize muscular anatomy for the bare-chested design
- Ninja model should have the bodysuit, mask, and headband as integral geometry
- Pavilion dimensions must be normalized after import from renderer bounds;
  prompt dimensions alone are not accepted as scale validation
- Pavilion floors and stairs must pass standability checks before gameplay use
- Courtyard and pavilion are separate assets and must remain independently
  scalable and positionable during engine composition
- Avoid coplanar overlap between the courtyard floor and any fallback floor
  renderer; only one first-floor visual surface may be enabled
- The shuriken must remain a separate rigid prop, with no baked hand or effect
